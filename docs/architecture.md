# Architecture

## Purpose and boundary

本项目是仅使用合成数据的临床前研究原型，验证医生优先的接诊工作流、受约束的数据投影、人工确认门槛和可审计的研究机制。它不是电子病历、医疗器械、诊断或处方系统。

SQLite 当前 migration 为 12。应用层、领域层、仓储和事务层分离，页面只能使用经过安全 Schema 验证的 DTO；页面不直接访问仓储。

## Product surfaces

医生主路径：

~~~text
首页
  -> 合成接诊选择
  -> 病历记录
  -> 模型参考
  -> 资料检索
  -> 诊疗复核
  -> 医生确认
~~~

研究治理路径独立于医生界面，负责确定性测试、结构化结果和安全导出。两条路径共享合成数据和安全核心，但不混用完成语义。

## Data flow

~~~text
页面与 Server Component / Server Action
  -> 应用服务
  -> Encounter、病历、资料、模型参考、复核领域
  -> 仓储与事务端口
  -> SQLite 或只读合成数据适配器
~~~

写入动作由应用服务协调运行模式、输入校验、PII 检查、来源绑定、并发保护、事务和审计。修订不可变，状态变化和对应审计在同一事务中完成。

## Encounter and records

一次接诊关联病例、当前病历修订和复核快照。病历正文由版本化 Schema 验证，记录状态与内容同时校验；空字符串、空数组和模糊的“暂无”不能绕过缺失状态。新修订不会修改旧修订，复核快照不会自动改绑新修订。

## Literature

资料功能只处理合成资料，包含流式导入、解析、确定性切分、检索和引用定位。资料名称、版本、格式和安全标识由服务端保存；引用只能定位到已通过投影和隐私门禁的资料摘录。真实教材不属于当前公开演示范围。

## Model reference

模型参考先生成服务端的病历事实与资料证据投影，再由模型服务返回固定结构。服务端验证 schema、事实 ID、资料 ID、引用和语言边界，并由服务端生成最终引用原文。模型不能覆盖来源、引用或安全元数据。结果只供医生参考，不自动写回病历。

## Speech

语音能力通过可替换的识别端口接入。当前仅为实验性语音功能；手工录入是可靠入口。录音只在医生明确操作后开始，待处理建议须经医生确认后才能进入病历，原始音频和完整转写不进入公开快照。

## Public demo

公开演示只读：不创建接诊、不保存病历、不写审计、不调用模型或语音服务，也不初始化可写数据库。所有可写路径都在服务端先检查运行模式，再检查数据库和外部能力。

## Non-clinical boundary

合成资料、结构化模型参考和诊疗复核只说明工程契约与医生确认流程，不证明临床准确率、诊断能力、处方能力、漏诊排除或生产可用性。
